# 经途·伴学 2.0：极简复原蓝图

> 这是一份面向重写者的实现说明，不是现有工程的逐文件解释。
> 目标是在保留主要产品能力和用户路径的前提下，用少量清晰模块重新实现平台。

## 1. 产品定位

正式名称：**经途·伴学**。

平台是由学生团队运营的零佣金家教信息门户，只负责：

- 学生/家长发布家教需求；
- 教师维护公开档案并浏览需求；
- 双方互相发现、建立会话并沟通；
- 教师分享学习资料，用户点赞、收藏；
- 用户提交评价、投诉和反馈；
- 管理员核验教师、处理内容和查看基本统计。

平台不负责支付、资金托管、线下履约、纠纷裁决和教学质量担保。

## 2. 重写原则

重写不是把旧文件换个目录，而是只保留真实业务概念。

1. 一个业务域一个深模块。模块内部直接完成鉴权、查询、写入和结果组装，对外只暴露路由表。
2. 不再把一个操作拆成 `schema.js + repo.js + api.js + mapper.js + display.js`。
3. 不做抽象预留。只有数据库、验证码供应商这类真实可替换对象才设接口。
4. 页面由数据驱动：请求数据、生成 HTML、绑定事件。避免多层状态同步。
5. 只保留影响业务结果的状态，不保存可以即时推导的字段。
6. 新库直接使用最终表结构，不编写历史迁移代码。
7. 错误处理只覆盖用户能够正常遇到的情况：未登录、无权限、对象不存在、输入为空、状态不允许。
8. 注释只解释业务原因，不复述代码。

### 明确删除

以下内容不进入 2.0 骨架：

- 全部自动化测试、架构检查、契约扫描和快照文件；
- 整个合同/约定域：表、路由、页面、聊天气泡、通知、后台入口和引导均不迁移；
- 旧版本兼容导出、历史字段兼容、表重建迁移和版本探针；
- 请求审计链、加密活动日志、遥测、指标刷新和发布就绪门；
- 哈希证据链、重加密工具和独立日志数据库；
- 限流表、多级限流、三振封禁、批量请求接口和边缘缓存；
- 二次认证 `capToken`、操作幂等键、并发赢家分支和重试补偿；
- 内容审核外部调用、地址文本侦测和重复的输入钳制；
- 前端请求重试、缓存失效协议、预取层和数据版本协议；
- 复杂首屏门、元素级缩放重排、装饰动画参数、新手引导定位引擎；
- 用于防止未来误改的重复常量镜像和守卫代码。

仍需保留最基本的登录、角色、数据归属和状态判断。它们是业务含义，不是额外防御。

## 3. 最终系统形状

系统只有三层：浏览器、Worker、D1。

```text
浏览器页面
  └─ api(path, options)
       └─ Cloudflare Worker
            ├─ 找到路由
            ├─ 读取当前用户
            ├─ 调用一个业务域模块
            └─ D1 持久化
```

推荐目录：

```text
家教平台2.0/
├─ package.json
├─ wrangler.toml
├─ build.mjs
├─ _worker.js                 # Worker 入口，仅转发给 server

│  ├─ db.js                  # D1 小适配器 + 最终建表 SQL
│  ├─ server.js              # 路由匹配、JSON 请求/响应、静态资源
│  ├─ auth.js                # 注册、登录、会话、验证码、当前用户
│  └─ domains/
```

- 非学科：乐器/音乐、声乐、绘画、舞蹈、书法、棋类、编程/机器人、体育/运动、演讲主持、语言口语；
- 学生年级：小一至小六、预备班、初一至初三、高一至高三；
- 教师阶段：大一、大二、大三、大四、硕士、博士、本科毕业、硕士毕业、博士毕业；
- 性别：不愿透露、男、女；
- 授课方式：线上、线下、均可；
- 性格标签：耐心、严格、幽默、温柔、逻辑清晰、亲和力强、认真负责、有方法、口语标准、善于鼓励；

- 上海区、街镇和经纬度数据。区域数据只是静态表，不应带业务逻辑。

不要把动画时长、弹窗宽度和 CSS 数值放进这个文件。视觉参数属于 CSS。

### 4.2 `db.js`

它是薄适配器，只提供：

```js
export const one = (db, sql, args = []) => db.prepare(sql).bind(...args).first();
export const all = (db, sql, args = []) => db.prepare(sql).bind(...args).all().then(x => x.results);
export const run = (db, sql, args = []) => db.prepare(sql).bind(...args).run();
export const batch = (db, statements) => db.batch(statements);
export async function init(db) { /* 执行最终 CREATE TABLE IF NOT EXISTS */ }
```

业务 SQL 留在所属业务域文件中。这样打开 `chat.js` 就能一次看见聊天的规则和查询，不需要跨三层追踪。

### 4.3 `auth.js`

对外接口保持很小：

```js
currentUser(db, request)          // User | null
requireUser(db, request, role?)   // User；失败抛 HttpError
createSession(db, user, device)   // token
destroySession(db, token)
requestCode(db, channel, target, scene)
verifyCode(db, channel, target, code)
routes                           // 登录注册相关路由
```

实现要点：

- 请求使用 `X-Auth-Token`；数据库只存令牌摘要；
- 密码使用 Web Crypto PBKDF2；
- 会话默认 7 天；
- 手机只接受中国大陆 `+86`；验证码 6 位、5 分钟有效；
- 教师注册需要邀请码，学生注册不需要；
- 保留用户名密码登录、手机/邮箱验证码登录和绑定；
- 用户注销时匿名化用户名并清除其业务数据。

不再实现多设备标签、三振封禁、限流、二次认证和凭证迁移。

### 4.4 `server.js`

所有业务域导出统一形状：

```js
export const routes = [
  ['GET', '/api/teachers', listTeachers],
  ['POST', '/api/teacher/profile', saveTeacherProfile]
];
```

`server.js` 只做四件事：

1. 将 `/api/...` 与路由表匹配，支持 `:id` 参数；
2. 对有请求体的方法读取一次 JSON；
3. 以 `{ db, request, url, body, params, env }` 调用处理函数；
4. 将返回值序列化为 JSON，未命中则返回 404，其他路径交给 `env.ASSETS.fetch()`。

建议处理函数直接返回普通对象：

```js
async function listTeachers(ctx) {
  const user = await requireUser(ctx.db, ctx.request);
  const teachers = await all(ctx.db, 'SELECT ...');
  return { teachers };
}
```

只保留一个异常类型：

```js
throw new HttpError(403, 'NO_PERMISSION', '没有权限');
```

除此之外让异常自然进入统一 500 响应，不在每层重复 `try/catch`。

### 4.5 `web/app.js`

前端只保留一个状态对象：

```js
const state = {
  token: localStorage.getItem('token'),
  user: null,
  page: 'landing',
  activeConversationId: null
};
```

以及四个通用函数：

```js
api(path, options)       // 自动加令牌，非 2xx 抛 Error
go(page, params)         // 更新页面并调用对应 render
html(strings, ...values) // 可选；简单模板助手
toast(message)
```

页面模块只导出 `render(root, params)`。页面内部加载自己的数据并绑定自己的事件；离开聊天页时停止轮询。不要建立第二份缓存状态。

## 6. 核心业务流程

### 6.1 注册和登录

1. 用户填写昵称、密码、角色。
2. 教师额外提交有效邀请码；邀请码用后标记 `used_by`。
3. 创建用户，密码存摘要。
4. 登录成功创建会话，浏览器保存令牌。
5. 可在设置页绑定手机号或邮箱，并使用验证码登录。
6. 管理员账号由部署环境中的用户名和密码在首次启动时创建。

### 6.2 教师档案与核验

1. 教师填写学校、年级、科目、报价区间、地区、时间、授课方式、性格、简介等资料。
2. 教师提交学信网核验码或录取通知书图片。
3. 管理员通过或拒绝核验。
4. 通过后 `teacher_profiles.verified=1`，公开资料显示认证标识。
5. 教师广场展示公开字段，不展示真实姓名、微信、邮箱和核验原图。

### 6.3 学生需求与匹配

1. 学生创建单科目需求。
2. 学生可编辑、删除、关闭或重新打开自己的需求。
3. 教师需求广场只显示 `open` 需求。
4. 学生教师广场按筛选条件显示教师，并可选择自己的一条需求计算匹配度。

匹配度计算：

```text
适用维度加权分 = Σ(维度得分 × 权重) / Σ(适用维度权重) × 100
```

维度规则：

- 科目 35：教师会教该学科/非学科项目为 1，否则 0；未填不参与。
- 地区 25：线上不参与；省份不同为 0；上海按街镇坐标距离计算，20km 线性降到 0。
- 预算 20：教师报价区间与学生预算区间按重合比例计分。
- 方式 10：线上、线下、均可按兼容关系计 1 或 0。
- 性格 5：命中偏好标签数 / 偏好标签总数。
- 性别 5：相同为 1，不同为 0，教师未透露时为 0.5；学生不限时不参与。

### 6.4 临时会话转正式会话

1. 任一学生或教师从广场向另一类角色用户发起会话。
2. 新会话为 `temp_status=init`，只有发起人能看到。
3. 发起人发送第一条消息后变为 `sent`，不能继续连续发送。
4. 对方回复第一条消息后，`temp_status` 变为 `null`，会话正式建立。
5. 正式会话双方均可持续发送文字、图片和文件。
6. 每方记录自己的最后已读消息 id，由此计算未读数。
7. 关闭临时会话时直接删除；关闭正式会话时保留历史但禁止继续发送。

### 6.5 帖子、评价、投诉和反馈

- 只有教师可以发布资料帖；帖子列表对访客开放。
- 登录用户可以点赞和收藏；作者或管理员可删除帖子。
- 学生与已认证教师建立正式会话且双方都发过消息后可以评价；评价经管理员审核后计入教师评分。沿用原平台加权算法：`(4.5 × 10 + 已批准评价总分) / (10 + 已批准评价数)`，初始评分 4.5。
- 投诉必须登录，可投诉教师、学生或帖子，并保存提交时的对象摘要。
- 反馈允许匿名提交；匿名用户用浏览器生成的 `client_token` 查询处理状态。
- 管理员将投诉或反馈标记为已处理，登录用户收到通知。

## 10. 现有 Flat 简约外观

本节只记录当前平台已经存在的 Flat 外观，供重写时复原。液态玻璃模式以及它的模糊、折射、光球、透明层和外观切换逻辑全部忽略。

### 10.1 整体印象

- 黑、白、冷灰构成主体，淡紫色作为唯一强调色；
- 页面平整、低阴影，层级主要依靠背景深浅、细边框、字号和留白；
- 带有轻微编辑设计感：超粗大标题、编号导航、细网格和灰色手绘线稿；
- 不走常见教育产品的蓝绿配色，也不使用卡通插画；
- 中文整体粗壮直接，英文和数字带几何无衬线风格。

主要视觉值：

```text
页面底色    #F4F5F7

```

字体沿用 `Space Grotesk + Noto Sans SC + 系统中文字体`。普通正文保持克制，首页口号使用极粗、紧行距的大号黑体。

### 10.2 品牌标识与装饰

- 品牌标识由四个小方块和“经途·伴学信息门户”文字组成；三个方块为黑色，一个为淡紫色；

- 线稿透明度低，只作背景，不承载交互；
- 其他业务页面不新增插画，保留大面积空白。

### 10.3 首页

桌面端占满视口，并以中线分成左右两半：

- 左上为品牌标识，右上为白底描边的登录、注册按钮；
- 左半主体是三行超大粗体口号“找家教 / 零佣金 / 更高效”，最后一行由黑渐灰；

- 入口卡是白色或浅灰色平面矩形，带细边框、圆角、两位紫色编号和右箭头；

### 10.4 登录与注册

- 整页使用统一浅灰背景；
- 表单是一张居中的白色矩形卡片，细灰边框、约 12px 圆角，无明显投影；

- 标签位于输入框左侧或上方，输入框使用浅灰填充；
- 主次按钮并排，均为平面填充或白底描边；

### 10.5 客户端框架

桌面端由固定左侧栏和浅灰主内容区组成：

- 左侧栏约 190px，白底，右侧一条细分隔线；
- 导航纵向排列，每项以淡紫色两位编号开头，例如 `01`、`02`；

### 10.6 筛选、卡片和表单

- 筛选按钮为浅灰平面按钮，右侧带向下箭头；

- 筛选项按行或列整齐排列，标签黑色，当前值为较浅灰文字，下拉箭头靠右；
- 教师卡、需求卡、帖子卡统一使用白色纸面、细灰边框和中等圆角；
- 卡片内部以粗标题、灰色说明、紫色编号或链接、少量标签建立层级，不增加彩色分类条；
- 输入框、下拉框和文本域以浅灰填充为主，聚焦时强化边框；
- 弹窗和确认框延续登录卡样式：白色纸面、灰边框、紧凑标题与按钮区。

### 10.7 聊天、通知和后台

- 聊天继续采用左侧会话列表、右侧消息区的平面分栏；

- 管理页面允许信息更密集，但编号、标题、按钮和纸面层级保持一致。

### 10.8 动效与交互

- 保留按钮按下、导航切换、弹窗出现、侧栏展开等短促反馈；
- 首页入口可以轻微淡入，但不复原玻璃模式的漂浮、折射和环境动画；
- 所有可点击项保持清楚的悬停、按下、禁用和键盘焦点状态；

`style.css` 只需依次描述页面底层、首页、客户端框架、通用控件、业务页面和移动端适配。不要照搬旧项目的玻璃 token、玻璃类名或覆盖链。

## 11. 推荐实现顺序

按可运行的业务闭环向外扩展：

1. 建立 `shared.js`、`db.js`、`server.js` 和最小页面壳。
2. 完成注册、登录、当前用户和角色导航。
3. 完成教师档案、学生需求和两个广场。

## 13. 重写时的判断准则

遇到旧代码时，只问三个问题：

1. 用户是否能直接感知这段逻辑？
2. 删除后是否会改变核心业务结果？
3. 它能否放进现有业务域模块，而不是新建一层？

前两项都是否，就删除。第三项可以，就不要创建新模块。

最终代码应让下一位开发者沿着这条路径读懂整个系统：

```text
页面动作 → 一个路由 → 一个业务域函数 → 一到数条 SQL → 返回页面所需数据
```

如果阅读一次用户操作仍需跨越五六个文件，说明重写再次走向了原工程的问题。
