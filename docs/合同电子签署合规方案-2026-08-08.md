# 合同电子签署合规方案（2026-08-08 · 调研结论）

## 背景与缺陷实证

用户反馈：合同上"签名者昵称没写上去"。调研实证（代码走查）：
- `server/contract.js` LEGAL_CLAUSES 落款是**空占位**「甲方确认：＿＿＿＿＿＿＿＿ 乙方确认：＿＿＿＿＿＿＿＿」，从未有代码写入确认人姓名与时间；
- `handleSignContract` 只置 `drafter_confirmed/other_confirmed` 标志，不写签名区块；
- `contract_ledger` 台账**只在双方确认后**记一条内容哈希链（ledgerRecord 仅在 both 分支），未记录单方确认事件、未存签署人身份与时间。

## 法律结论（无需 CA，靠"约定的可靠条件"）

- 《电子签名法》13 条 2 款：当事人可约定电子签名的"可靠条件"；普通家教服务合同不在排除清单（3 条 3 款），**无需 CA 数字证书**（16 条仅强监管行业要求第三方认证）。
- 平台现有链路已构成可靠条件：实名账号登录 + capToken 密码二次确认（专有+仅本人控制）+ 服务端时间戳 + 内容哈希防篡改链（append-only INSERT）+ verify 接口。
- 留痕四要素闭环：**身份**（账号/capToken）+ **意愿**（30 秒阅读+二次确认+密码）+ **时间**（服务端 UTC）+ **内容**（SHA-256 哈希链）。目前缺"谁/何时"落进合同正文本身。
- 平台无独立昵称字段（users 仅 username，用户名即展示名）——签名区块用平台账号（合同头部甲方/乙方名）作签署人标识即可；教师侧后续可叠 `teacher_profiles.real_name`。
- 明确不做（过度设计）：CA/第三方电子签名平台、区块链/RFC3161 可信时间戳、独立 signature_log 表、人脸活体。

## 改造规格（实施时按此）

### 1) 签名区块内嵌 contract_md（mdRender 仅支持 # 标题 + **加粗**，模板须兼容）

- 从 LEGAL_CLAUSES 末尾**删除空占位行**「甲方确认：＿＿ 乙方确认：＿＿」（缺陷源头）。
- 新增 `buildSignatureBlock({...studentName/studentUsername/teacherName/teacherUsername/studentSignedAt/teacherSignedAt/both/contractId})`，以 `<!-- 签署记录 -->` marker 包裹，追加在 LEGAL_CLAUSES 之后（与 CONTRACT_BUSINESS_END 同源定位语义）。
- 模板：`## 第十条 签署记录` + 双方确认声明 + 甲方/乙方各一行「**姓名**（平台账号 xxx）」+「签署状态：已签署 / 待签署　签署时间：xxx」+「平台存证：全文 SHA-256 指纹已纳入防篡改存证链（存证流水号 #CD{contractId}）……」
- **不自引用哈希**：区块内只放合同编号流水号，原始哈希经 `/api/contracts/:id/verify` 在存证校验面板展示（避免"先有哈希才生成正文"循环）。

### 2) 服务端每次签署落一条台账 + 重写正文

- contracts 表 ensureColumns 补 `drafter_signed_at` / `other_signed_at`（TEXT DEFAULT ''，存 UTC ISO）。
- `handleSignContract` 改造（全部在既有 winner 分支，changes>0 才副作用）：
  1) 条件 UPDATE 与 confirmed 标志同句置位 signed_at；
  2) 读更新后行；3) 依双标志 + signed_at + 会话双方名拼签名区块，重拼 contract_md 加密回写；
  4) 双方已确认 → 既有 claim UPDATE status='signed'（赢家）；5) **ledgerRecord 每次签署都记**（不再仅 both）。
- 台账哈希输入不变（bodyHash 因正文已内嵌签名区块而自然覆盖"谁签/何时签"）；verify 最新条目重放逻辑不变。
- 修改合同（PUT）须同步清空 signed_at 两列；旧签名区块由 contractWithLegal 重拼自动丢弃（位于法律条款之后），语义天然成立。

### 3) UI

- 合同列表卡：`signing` 态在状态 tag 旁补「甲方已签 · 乙方待签」（由 drafter_confirmed/other_confirmed 推导）；`signed` 显示「双方已签署」。
- 签署弹窗：底部加「你将以平台账号「{username}」电子签署本合同」前置告知。
- 存证校验：toast 升级小面板，展示 contentHash、台账条目数与各条 created_at（verify 接口已返回，可扩展）。
- 合同查看弹窗：正文末尾即签名区块，随 mdRender 渲染。

### 4) 低成本加分（本任务内建议）

- 第九条「生效与存证」补一句：把"账号登录 + 二次密码确认 + 服务器时间戳 + 内容哈希"作为双方约定的可靠电子签名条件明文钉进合同（13 条 2 款），零新机制。

### 5) 后续（本任务外）

- 注册/签署前补实名核验（手机号三要素）——纯账号密码/仅手机号的弱认证已有败诉判例，且契合《网络安全法》24 条实名义务；
- 学生端未成年时建议家长/监护人账号作为签约主体。
