# 0.31-wizard-ui.md — 需求录入 wizard 重构设计（v0.31.7）

## 背景与用户原话
用户三件事：①「详细偏好」拆成「教学目标」+「教师偏好」，教师偏好放成绩情况后；②学科/非学科切换
必须联动成绩页（非学科改名「技能现状」+ 每技能文本框）；③UI 优化（统一高度 / 侧滑+淡出入切换 /
进度条串点 / 完成态不跟当前页）。并点名批评：此前没调研现代成熟方案就俺寻思。

## 调研结论（联网，非俺寻思）

### 1. 页切换动画（多步表单成熟方案）
- 主流 = slide + fade 组合；方向一致性：前进旧页左滑、新页从右进，后退反向。
- 时序：总 ~400ms、50% 步重叠；退出 ~250ms ease-in → 进入 ~300ms ease-out；prefers-reduced-motion 时降级瞬时。
- **核心实现 = 滑动轨道（sliding track）**：所有步骤并排在一个 flex track，视口 overflow hidden，
  每步 min-width:100%，前进 translateX(-step×100%)。**步骤 DOM 常驻 → 来回切换不丢输入状态**
  （对比 display 切换：语义保留但我们已 DOM 常驻，轨道方案让"侧滑"自然成立）。
  参考：vanillajs-smartwizard（slideHorizontal+fade）、react-form-steps（slide/fade）、
  framer-motion fade+slide 组合、Actipro WPF Wizard transition-effects。
- 单索引驱动：轨道位置、进度、按钮态都由一个 step 索引/状态集合驱动，不散落多处。

### 2. 进度条完成态（Steps/Stepper）
- Ant Design Steps：status = wait/process/finish/error，**由 current 索引派生**（current 之前的全 finish）。
- MUI Stepper：activeStep + **completed 独立标记**（不自动派生）；线性模式顺序完成、非线性可任意进入。
- **用户语义 = MUI completed 独立于 activeStep**：「填写完的点染紫色 = 新建时完成过填写的、编辑时翻到过的
  页面，不是当前停留页面之前！进度条推进同理，不跟当前停留页走」——明确否定 Ant 式「当前页之前全 done」。
  → 设计：done/visited 集合独立记录，当前页 = process，未到 = wait。

### 3. 教学需求字段（教育平台需求表单）
- 主流平台需求发布 = 分步引导（科目 → 时间 → 预算）；「教学目标/教师偏好」无现成统一标准。
- 教学目标 → 按常见辅导诉求设计为**标签多选**（提分/培优/竞赛/兴趣培养/习惯养成/考前冲刺），tag-pick 组件。
- 教师偏好 = 偏好性格（tag-pick）+ 偏好老师性别（select），归并原 P4「详细偏好」。

## 设计定案

### 页面结构（8 页）
P1 省份 → P2 教学方式+授课区域 → P3 学生性别+年级 → P4 科目（类型切换+学科/非学科+**教学目标**）
→ P5 成绩情况/**技能现状**（按类型即时切换）→ P6 **教师偏好**（偏好性格+偏好性别，移自 P4）
→ P7 预算+期望时间 → P8 提交者+联系方式+补充说明。

### 数据
- `teaching_goal`：教学目标，字符串数组（白名单标签，≤2），demands 加列（ensureColumns）+ 提交/回填。
- `skill_notes`：非学科技能描述，`[{project, note}]`（白名单项目 + note 长度上限），demands 加列 + 提交/回填。
- 服务端 sanitizeDemand 钳制/白名单（同 target_subjects 口径，静默截断）；mapper 透传。

### 切换动画（R3-2）
- 7/8 个 .dw-step 包进 .dw-steps-track（flex，每步 min-width:100%）。
- JS 只写 `--dw-step-active`（数字索引）到 #demand-form（CSS 变量驱动，JS 不写 inline transform——
  符合「JS 只切类/变量，动画全在 CSS 呈现层」铁律；参考 ui-scale-reflow 合成器只读经验）。
- CSS：.dw-steps-track `transform: translateX(calc(var(--dw-step-active) * -100%))` + transition
  transform 300ms ease；步内元素 opacity 淡入（.dw-step--active 时）。后退方向由动画类切换。
- 视口 .dw-steps-viewport：overflow hidden + 统一高度（见 R3-1）。

### 统一高度（R3-1）
- .dw-steps-viewport 固定 min-height（CONFIG.UI 常量，如 360px，随 --ui-scale），内容超高
  viewport 内 overflow-y:auto（成熟多步表单视口定高内滚惯例）。页面间高度不再跳变。

### 完成态（R3-3/R3-4）
- 集合驱动：`demandWizardDone = new Set()`（校验通过过）+ `demandWizardVisited = new Set()`（翻到过）。
  - 新建：demandWizardNext 校验通过 → done.add(n)。
  - 编辑：prefill 后 P1 标记 visited；demandWizardGoTo(n) → visited.add(n)；
    （编辑模式进入页也视为已完成过的填写——用户「编辑需求里边用户翻到过的页面」= visited）。
- 进度条：点染紫 = done ∪ visited；当前页 = 实紫+光圈（process）；其余 = wait 浅描边。
- 进度条连接线推进 = done∪visited 的连续前缀（从 P1 起连续段实紫），不跟当前页。
- 删旧逻辑：demandWizardGoTo 里 `ch.classList.toggle('done', s < n)`（当前页之前全 done）——违反用户语义。

### 类型切换联动（R2）
- setDemandType 扩展：切非学科 → 清空 #d-scores 学科成绩行、P5 标题即时改「技能现状」、
  按勾选项目渲染技能文本框（描述/证书/考级/获奖）；切回学科 → 恢复「成绩情况」+ 按科目渲染成绩行。
- 技能文本框数据：collectSkillNotes/prefillSkillNotes。

## 实现顺序（基元任务）
R1-2 字段+数据（teaching_goal/skill_notes）→ R1-3 页面重排 → R2 类型联动 → R3-1 统一高度 →
R3-2 侧滑动画 → R3-3/4 进度条+完成态 → 测试 → 部署验证。
