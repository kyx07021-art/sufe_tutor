# 架构现状与待开发清单（2026-08-02 快照，版本 v0.19.44）

> 本文档给项目所有者与合作者参考：当前系统的**前端/后端架构现状**、**明确还欠的功能**、**公测前必办事项**。
> 配套阅读：`docs/architecture.md`（搭积木指南：加页面/加写操作/改文案的配方与硬性约定）、`docs/backlog.md`（结构/视觉待办队列与历史复盘）。
> 本文是快照——版本迭代极快（0.19.x），关键结论已同步进相应代码注释，大改架构时请更新本文。

## 0. 一页速览

- **形态**：Cloudflare Pages 全静态前端 + Worker 后端 + D1 数据库，零框架、零构建、原生 JS（经典脚本全局函数 + 内联 onclick）。
- **前端**：单页应用 `index.html` + 8 个业务 JS + 5 个 CSS；玻璃视觉引擎 glass.css（参数接口），结构层 style.css。
- **后端**：`_worker.js` 只做路由/静态回退/限流/留档，业务拆 `server/*.js`（19 个文件）；`db.js` 是唯一写 SQL 的数据层。
- **身份**：X-Auth-Token 令牌（库内只存 SHA-256 摘要）；管理员 = users.role='admin'；危险操作密码二次认证换一次性 capToken。
- **安全基调**：赢家模式（条件 UPDATE + changes>0 才执行副作用）、敏感字段 AES-GCM 落库、留档加密 + 脱敏、门牌号守卫、svg 全站拒收、令牌 mask。
- **部署**：git push 自动部署，push 后 curl /api/health 验线上；`npm test` 34 用例（node --test，纯函数 + 数据层）。
- **当前状态**：核心业务流程完整闭环（注册邀请码 → 需求/教师双广场 → 意向/推送 → 会话 → 合同签署/撤销 → 评价审核 → 留档审计）。剩余待办以**公测前安全事项**与**体验增强**为主。

## 1. 前端架构现状

### 1.1 文件清单（加载顺序即 index.html 中的顺序，是硬契约）

| 文件 | 职责 |
|---|---|
| `index.html` | 唯一 HTML：全部视图骨架 + 液态玻璃背景舞台生成器（读 constants.LG 换算 :root 变量、生成光球/发光圆） |
| `constants.js` | 全站常量单源：业务枚举、`LG` 玻璃观感配置、`APP_VERSION`、约 600 条 UI 文案。**前端与 Worker 双端同读**（改文案只动这一个文件） |
| `region-data.js` | 31 省高考政策数据单源（3+1+2/3+3/传统、赋分档位），双端共用 |
| `app-display.js` | 统一显示层（纯函数）：科目/性别/学段/省份名、星级、匹配度、墓碑用户名等「数据→展示文本」唯一收口 |
| `app.js` | 壳与状态层（130KB，最大）：state、api()、escHtml、视图切换、登录通路、invalidate 缓存协议、loadInto 装载器、轮询、openModal 弹窗壳、浏览教师、需求卡（四上下文共用）、意向/推送、通知、账户、档案编辑、评价、反馈 |
| `app-region.js` | 地区赋分组件库：省份下拉、高考编辑器（按政策三支渲染）、等第/分数制页签、成绩收集 |
| `app-posts.js` | 资料共享广场：列表/搜索/排序、mdRender（markdown-lite 自研，先转义后识别，图片仅放行 http(s)/位图 dataURL）、发布/删除、管理员广播 |
| `app-chat.js` | 我的会话：双栏壳、4s 轮询（sinceId 增量 + 防重入 + 过期响应丢弃）、附件暂存/上传（XHR）、图片压缩 |
| `app-contracts.js` | 合同：三态列表、确认签约（reAuthModal 密码重认证）、修改（乐观锁）、撤销（两级确认）、存证校验 |
| `app-admin.js` | 管理员面板：统计、用户/需求（keyset 游标分页）/评价/帖子/合同/反馈管理、封禁、邀请码签发 |

CSS 分工：**style.css = base 结构层**（令牌/布局/文字），**glass.css = 玻璃视觉引擎**（后加载覆盖），style-region/posts/chat 为各模块专属结构样式。

### 1.2 视图/页面体系

- 双层：外层 `showView()` 切 5 个视图（landing/login/register/invite-gate/client）；内层客户端壳内 `selectPage()` 切 17 个 `data-page` 页面区。
- **ROLE_PAGES 注册表**（app.js 顶部）：侧边栏完全由它渲染，`{student:[…], teacher:[…], admin:[…]}` 每条 `{id, label, desc, enter, auth?}`。加页面三步：改注册表 + index.html 加 section + 写 enter 函数。
- 访客模式：主页按钮设 guestRole 直接逛公开页（浏览教师/需求大厅/资料共享/about），需身份的操作经 `ensureAuth()` 统一登录通路并自动返回原页面。
- 页面持久化：`localStorage.sufe_page` 刷新回原页签；401 兜底自动汇入登录通路。

### 1.3 状态与数据流

- `state` 单对象 + 各模块级全局（聊天/帖子/管理的局部状态）。
- **缓存协议**：缓存只有一份（state.* 数组），`invalidate(key)` 置空重拉；任何改数据的操作成功后必须 invalidate。
- **loadInto(elId, fetcher, renderer, opts)**：loading → 取数 → 空态/渲染/浮入四件套单源，seqKey 乱序守卫。
- **轮询矩阵**：聊天 4s 增量、侧边栏红点 30s、邀请码倒计时 1s、推送冷却 1s。全站无 WebSocket/SSE（有意决策）。
- 令牌：sessionStorage 默认 / localStorage 勾选记住（7 天），启动经 /api/auth/me 验证恢复，绝不重放密码。

### 1.4 玻璃视觉引擎（glass.css）

- 元素带 `glass` 类即接入；参数接口 `--g-fill`（填充唯一源）/`--g-fg`/`--g-r`/`--g-lift`/`--g-frost`/`--g-liquid`（液态弯月边缘）/`--g-hover`/`--g-ring`；浮层件加 `glass--float`、实心小件 `glass--solid`。
- 三条 `:where()` 主规则零特异性，组件自有定位胜出；观感配置单源 `constants.LG`（改观感只动 constants）。
- 性能分层：玻璃体 = 半透明填充 + 弯月边缘零重滤镜；真磨砂同屏仅 1-2 件；全站唯一真模糊是背景底板。

### 1.5 渲染纪律

全局函数 + 内联 onclick（CSP 需 unsafe-inline，有意取舍）；**escHtml 是所有插值必经转义口**；弹窗单源 `openModal`，禁浏览器原生 confirm（二次确认走 confirmDanger/openConfirmModal/reAuthModal 三件套）；时间统一 `fmtDateTime()`。

## 2. 后端架构现状

### 2.1 入口与路由（_worker.js）

职责严格限定：路径解码防绕过 → CORS → 静态回退（敏感路径 `/server/` `/docs/` `/secrets.js` `*.md` 等硬 404）→ DB 惰性初始化（Promise 单跑迁移）→ 请求体 1.1MB 双保险 → 限流三层 → 路由分发 → 全量留档包裹（500 也留）。

路由分区：auth / admin / feedback / teacher / demand / intent / push / notify / contract / chat / review / post / health。未命中 404。

### 2.2 服务端模块（server/*.js）

| 文件 | 职责 |
|---|---|
| `core.js` | 共享底座：json/error、dbAll/dbGet/dbRun、PBKDF2-SHA512 口令哈希、SHA-256 令牌摘要、capToken、authUser（JOIN auth_sessions）、requireAdminOrError、STATUS/MSG、ADDRESS_GUARD、限流辅助 |
| `db.js` | **唯一写 SQL 的数据层**（19 张表）：全部 DDL/迁移、safeJsonArray 单点反序列化、mapper 出口剥私密字段、价格 null 语义、评分重算、注销清理、管理员统计与 keyset 分页。路由层零裸 SQL、零 JSON.parse |
| `contract.js` | 合同状态机（pending→signing→signed）+ 台账（SHA-256 哈希链，verifyChain 全链校验）+ 依《民法典》470 条生成九条合同 Markdown |
| `log.js` | 留档咽喉：logEvent（detail 脱敏 + AES-GCM 加密 + 截断）、logRequest（HTTP 全量兜底）、管理员检索（密文降级：过量取 → 解密 → JS 过滤） |
| `fieldcrypto.js` | AES-GCM-256 原语收敛（enc:v1:iv:ct 格式，与 log.js 互读；解密失败 [undecryptable]） |
| `notify.js` | 通知：notifyUser 咽喉（吞错/截断 200 字）、广播（全体插行）、GET/已读/批量删。自持建表避免循环依赖 |
| `secrets.js` | 敏感配置网关：env Secrets 优先，回落本地明文（内测期有意，见 §4.3） |
| `routes-*.js` | 各域关口层（鉴权/校验/业务组合） |
| `sms-auth.dormant.js` | **休眠模块，不接路由**：短信验证码认证骨架，transport 均为 TODO 桩 |

依赖纪律：单向（worker → routes → db/core → secrets）；log/notify 刻意不依赖 db.js 防循环；文案单源 constants.js（routes-posts.js 的 PMSG 是注释声明的唯一例外）。

### 2.3 数据层要点

- 19 张表：users / auth_sessions / rate_limits / teacher_profiles / student_demands / reviews / contracts / invite_codes / demand_intents / conversations / messages / posts / post_likes / demand_pushes / uploads / feedbacks / notifications / activity_log / contract_ledger。
- 迁移一律幂等 + ensureColumns（PRAGMA 探测后 ALTER）；大迁移用改名腾位规避 D1 强制外键。
- 库内 UTC（datetime('now','localtime')），前端统一 fmtDateTime；mapper 出口剥私密字段（mapDemandRow 默认剥联系方式/address_detail；Full 版仅本人/管理员）。

### 2.4 安全机制

- 身份：X-Auth-Token 唯一；库内只存 SHA-256(token)；注销吊销全部会话；管理员统一 requireAdminOrError 单点。
- **赢家模式**：一切并发状态迁移用「条件 UPDATE WHERE status=旧态」+ changes>0，副作用只归赢家（意向/推送/邀请码消费/需求重开/合同签约/撤销/取消）。
- 乐观锁：合同修改必须带 updatedAt。
- 限流三层：内存 per-isolate + D1 持久化桶 + 三振封禁（10 分钟 3 超限封 15 分钟）。
- 字段加密：联系方式/真实姓名 FIELD_ENC_KEY（回落 LOG_ENCRYPT_KEY）AES-GCM 落库。
- 门牌号守卫 ADDRESS_GUARD（需求/档案写入点校验）；svg 全站拒收（头像/证件/聊天附件/帖子渲染）。
- 500 回显脱敏；危险操作 capToken 二次认证。

### 2.5 部署与运维

- 无 wrangler.toml：D1 绑定经 CLI/控制台；`npm run deploy` 兜底（pages deploy --branch main 直指生产）。
- git push 自动部署；push-retry.sh 重试推送；push 后 curl /api/health 验线上；版本探针 + constants 双匹配后才发公告。
- CI：`.github/workflows/ci.yml` npm test。测试 34 用例覆盖纯函数与数据层（crypto/log-crypto/log-sanitize/contract-chain/admin-demands-pagination），**routes 层与 _worker.js 无自动化测试**（盲区，见 §3）。
- 独立库模式：LOG_DB / LEDGER_DB 绑定即启用，未绑定回落业务库，零代码改动。

### 3.2 架构取舍（已实现、有意简化，知悉即可）

- 聊天 4s 轮询而非 WebSocket（短消息场景够用）；限流内存层 per-isolate（重启清零，多实例部署会失效）。
- 头像/附件为 dataURL 大字段存 D1（~500KB 上限，无病毒扫描，仅前缀/黑名单过滤）。
- 日志检索 q 在密文下降级（最多取 500 条解密再过滤，量大不准且贵）。
- 匹配度为纯前端计算（科目 60 + 区县 20 + 预算 20，无历史/排序权重）。
- 合同正文是 Markdown 生成而非正式 PDF；签约以密码二次认证代替短信验证。
- CORS 全开（`*`）、CSP unsafe-inline（内联 onclick 架构所需）——均有意。
- 注销用户墓碑展示（用户名灰斜体「已注销用户#id」，数据保留）。

### 3.3 公测前必办（安全/运维，多数有书面计划）

1. **【最高优先】secrets.js 明文迁移 + 管理员凭据重置**：Git 历史自 first commit 起含 `admin_sufe/admin_sufe` 明文与 LOG_ENCRYPT_KEY（网安复测 F-01 仍残留）。步骤见 `docs/secrets-plan.md`：上传 7 个 Worker Secrets → 清空本地 secrets.js → **轮换管理员密码 + 吊销全部 auth_sessions + 轮换 LOG_ENCRYPT_KEY**（旧密文解密重加密或只读封存）。
2. **独立 FIELD_ENC_KEY**：当前字段加密回落共用 LOG_ENCRYPT_KEY——日志轮换密钥会连带业务字段密文作废，公测应拆独立密钥。
3. **邀请码门控决策**：`INVITE_GATE_ENABLED=true`（后端）+ 前端邀请码页。公测维持邀请制还是放开注册，未定。
4. **管理员口令强度**：种子口令 `admin_sufe/admin_sufe`，公测必须重置。

## 4. 新合作者上手指南（最短版）

1. **本地跑**：`npm run dev`（wrangler pages dev + D1 绑定，见 package.json）；无 D1 时可先看测试理解数据层。
2. **改文案**：只动 `constants.js`（UI 块 / MSG 在 server/core.js 只 re-export）。
3. **加页面**：ROLE_PAGES 注册表 + index.html section + enter 函数（详见 docs/architecture.md 配方）。
4. **加写操作**：db.js 写数据函数 → routes-*.js handler → _worker.js 路由一行 → 前端 api() 调用 → 成功后 invalidate。**服务端写路径必须带同款门禁**（归属校验/状态条件/赢家模式）。
5. **必守纪律**（CLAUDE.md 全文值得一读）：删除优先（加任何东西前先反思能否靠删实现）；token 一律 mask；escHtml 必经；mapper 出口剥私密字段；路由层零 JSON.parse；注释要跟实现同步（本仓库刚清过一轮过时注释）。
