# 合同模板（v2 当前生成格式）

> 需求 RC（2026-08-22）：给团队成员参考「我们现在生成的合同格式」。
> v2 **没有独立的合同模板文件**——合同正文由服务端在起草时动态生成（`src/server/domains/contract/api.js`：`buildContractMd` + `LEGAL_CLAUSES` + `buildSignatureBlock` 三段拼接）。本文件把最终成稿格式原样呈现，变量处用 `[变量]` 占位、留空代填。
> 正文为 Markdown，前端渲染仅支持 `#` 标题与 `**` 加粗两种语法。

## 一、完整合同格式（模板）

```markdown
# 家教服务合同

**甲方（学生方）**：[学生姓名]
**乙方（教师方）**：[教师姓名]
**关联需求编号**：#[需求编号]
**签署日期**：[起草日期]

甲乙双方本着平等、自愿、诚实信用的原则，依照《中华人民共和国民法典》及相关法律法规，经友好协商，就家教服务事宜达成如下协议：

## 第一条 服务内容与授课安排

1. 授课方式：[线下授课 / 线上授课]。
2. 授课科目与内容：详见本合同第三条「教学方案」。
3. 首次上课日期：[首次上课日期，未填时「由双方另行协商确定」]。
4. 授课时间：[时间表，未填时「由双方另行协商确定」]。
5. 授课地点：[授课地点；线下未填时默认「甲方常住处或双方另行约定的地点」，线上默认「双方约定的线上课堂」]。

## 第二条 课时费与支付

1. 约定时薪为每小时 **[金额]** 元（人民币）。
2. 薪资结算方式：[次付 / 周付 / 月付 / 自定义，未选时「由双方另行约定」]。甲方应按约定如期支付课时费用。
3. 试课薪资方案：[第一次试课免费 / 第一小时免费，第二小时起按约定时薪收费 / 试课全程正常收费 / 自定义，未选时「由双方另行约定」]。
4. 平台仅提供信息撮合与合同存证服务，不参与任何费用结算，不代收、不代付课时费用。课时费由双方在站外自行协商并直接结算（如微信、支付宝转账等），平台不对站外资金往来承担任何责任。

## 第三条 教学方案

[教学方案：起草表单自由文本，支持 H2/H3/加粗，未填时「（未填写）」]

<!-- 业务条款结束，以下法律条款由平台固定，不可修改 -->

## 第四条 甲方权利与义务

1. 有权要求乙方按照约定的内容与时间安排授课，并对教学质量进行监督；
2. 应按约定支付课时费，并为授课提供必要的学习条件与配合；
3. 如需调整课程安排，应提前与乙方协商并达成一致；
4. 对通过平台获取的教师个人信息，仅用于本次家教服务目的，不得向第三方泄露。

## 第五条 乙方权利与义务

1. 有权按约定获取课时报酬；
2. 应按约定认真备课、授课，保证教学质量；
3. 如需调整课程安排，应提前与甲方协商并达成一致；
4. 对授课过程中知悉的学生个人信息与学习情况予以保密，不得向第三方泄露。

## 第六条 课程调整、补课与违约责任

1. 任一方无法按时上课，应提前通知对方，并协商安排补课或调课；
2. 因一方过错给对方造成损失的，双方应友好协商解决；
3. 任一方严重违反本合同约定的，另一方有权解除本合同，违约方应承担相应责任。

## 第七条 合同的变更与解除

经双方协商一致，可以变更或解除本合同；任一方提前终止合同的，应提前告知对方，并妥善结清已发生而未支付的课时费用。

## 第八条 争议解决

因履行本合同发生争议，双方应首先友好协商解决；协商不成的，可依法向有管辖权的人民法院提起诉讼。

## 第九条 生效与存证

本合同自双方在平台内确认签约后生效，双方账户内各存一份，内容相同。平台对签署时的合同文本及其数字指纹（SHA-256）进行独立留档，供任一方事后校验文本一致性。

双方约定：以平台账号登录、签署时密码二次确认、服务端签署时间戳以及全文内容哈希存证，共同构成本合同电子签署的可靠条件（《中华人民共和国电子签名法》第十三条第二款），与手写签名或盖章具有同等法律效力。

---

## 第十条 签署记录

双方确认：以下签署人已通过本人平台账号完成实名登录，并凭本人密码二次确认表达签署意愿；平台服务端记录签署时间并留存全文指纹，作为本合同的电子签署凭证。

**甲方（学生方）**：
**[学生姓名]**（平台账号：[学生姓名]）
签署状态：已签署　签署时间：[签署时间]（未签时「待签署」）

**乙方（教师方）**：
**[教师姓名]**（平台账号：[教师姓名]）
签署状态：已签署　签署时间：[签署时间]（未签时「待签署」）

平台存证：本合同全文 SHA-256 指纹已纳入防篡改存证链（存证流水号 [合同编号]），任一方可随时通过平台「存证校验」核对文本一致性。
```

## 二、变量来源表

| 变量 | 来源 | 说明 |
|---|---|---|
| 学生姓名 / 教师姓名 | 会话双方用户名（服务端 JOIN users） | 合同签署记录中「平台账号」即用户名，无独立昵称字段 |
| 需求编号 | 起草时选择的签约需求 | 无关联需求时该行整体省略 |
| 签署日期 | 服务端起草时间（createdAt） | 服务端 UTC 起草日期（yyyy-mm-dd）内嵌进正文（api.js:336） |
| 授课方式 | 起草表单「教学方式」下拉 | offline→「线下授课」，其余→「线上授课」 |
| 首次上课日期 | 起草表单日期选择 | 未填时兜底「由双方另行协商确定」 |
| 授课时间 | 起草表单时间表（可多时段） | 未填时兜底同上 |
| 授课地点 | 起草表单自由文本 | 隐私合规：仅模糊表述（如「甲方常住处」），**不收集详细门牌号**；未填时按方式给默认 |
| 时薪金额 | 起草表单「约定时薪」 | 前端表单必填 > 0；服务端钳制 `[0, BUDGET_MAX]`（api.js:300） |
| 结算方式 | 下拉：次付/周付/月付/其他 | 选「其他」时带入用户自拟文字，未选时兜底「由双方另行约定」 |
| 试课方案 | 下拉：首课免费/首时免费/正常收费/其他 | 同上 |
| 教学方案 | 起草表单自由文本（支持 H2/H3/加粗） | 授课科目与内容落在此条，未填时「（未填写）」 |
| 签署时间 | 服务端签署时间戳 | 第十条由服务端按当前签署态动态生成，修改/重签自动重建 |

## 三、三段生成结构

合同正文 = 三段拼接（`contractWithLegal` + `buildSignatureBlock`），存于 `signing_contracts.contract_md`：

1. **业务部分**（第一条~第三条）：起草表单字段由 `buildContractMd` 拼装（`api.js:137-175`）。
2. **固定法律条款**（第四条~第九条）：平台写死的 `LEGAL_CLAUSES`（`api.js:46-82`），**不可修改**；保存时自动重拼，分隔哨兵 `CONTRACT_BUSINESS_END` 防止用户文本越过法律区（`api.js:43`）。
3. **签署记录**（第十条）：`buildSignatureBlock` 动态生成「谁签/何时签」+ 存证流水号 `#CD{id}`（`api.js:98-116`），位于法律条款之后，每次签署/修改重拼。

存证：每次签署在 `contract_ledger` 台账追加一条（正文哈希 + 合同 id + 时间 + 前序哈希的链式指纹），篡改任一条即断链，`/api/contracts/:id/verify` 供任一方校验文本一致性。

## 四、与新版模型的差异提示

v2 模板是「签约态推进 + 绑定需求」时代的产物（需求编号行、授课方式/时薪/结算/试课等字段均来自签约上下文）。新站模型下合同**独立、不绑需求、全字段自填**——法律条款与三段拼接结构可直接复用，业务部分字段采集需按新站重设计。
