# 新站重构执行定案（build-plan）

> 开工前定案（2026-08-22，六点开干）。配套文档：`docs/新前端需求.md`（用户计划书=真源）、`docs/new-frontend-3-tier-workflow.md` §12（执行定案）、`docs/interfaces.md`（接口帽骨架）、`docs/v2-reuse-boundary.md`（后端考古依据）。
> 本文件 = 模块拆分 + 基元群清单 + 依赖 + 执行序。逐条基元拆解是开工后阶段一的工作（模块 agent 细拆），本文只给模块级 + 基元群粗拆。

## 0. 范围与边界（用户定案）

**做**：删旧前端（branch 上）→ 新前端全量（按计划书）→ 后端考古组装重写 → 前后端并行 → 合并替换 main。
**不做**：起草合同组件（计划书 C2.4 草稿保留，加号上拉栏先不放选项，合同前端组件全部不写，合同后端独立化仍做，接口帽预留）；B3 资料广场（占位灰字）；签约一切。
**质量原则**：每基元一次做到最好（含动效/交互细节），禁止「先能用后精」；时间成本用户担得起。

## 3. 依赖矩阵

- **M0 无依赖，最先冻结**（所有模块的公共地基）。
- **interfaces.md 先于所有页面模块**（接口帽契约）。
- M1/M2 依赖 M0；M3-M9 依赖 M0 + interfaces（M4/M7 最重，M3/M4 含复杂动效）。
- M6 可复用 v2 captcha 前端滑块经验（考古 v2 `src/client/core/captcha.js`）。
- **后端 S0 先行**（地基）→ S1-S6 并行；S2 临时会话、S4 新匹配度、S5 合同独立化与前端 M4/M7/M8 同批。
- 前后端只经 `interfaces.md` 耦合，互不阻塞（前端先接接口帽 dummy）。

## 4. 开工执行序（六点，含 branch）

1. **branch 就位**：`git checkout -b <branch>`（如 `new-site`）+ 旧 main 打 tag `v2-legacy-final` → main 冻结。
2. **Pages preview 确认**：分支部署开关（preview URL 可用性）。
3. **阶段一**：本文件模块拆分派复核 agent（W27c，PASS 才开工）→ 10 前端模块 + 6 后端模块各派 agent 细拆基元（读计划书 + build-plan + interfaces 骨架）→ 汇总全站基元清单（写回 CLAUDE.md 需求单精简版 + 文档详版）。
4. **阶段二**：主会话实现 M0 组件基础层（按计划书规格，一次做到最好）+ 签发 `interfaces.md` 全部接口帽（cap/ready 状态）→ 模块 agent 评估承载力 → 冻结。
5. **阶段三**：前端 9 模块 + 后端 5-6 模块并行开发（每基元一次到位 + 独立审计异步池；复杂动效基元 5 agent 方案）。
6. **阶段四**：收口联调 → 全站走查（真实用户视角/对抗性验证）→ **数据迁移演练**（d1-migration-drill 模式）→ 合并替换 main → 线上验证 + 回滚点（tag）保留。

## 5. 里程碑

- **M1（基础层冻结）**：M0 组件库可用 + interfaces.md 签发完成 → 模块并行解锁
- **M2（主链路跑通）**：落地页 + 认证 + 会话 + 教师广场核心可用（可演示）
- **M3（全量完成）**：全部模块完成 + 收口联调绿
- **M4（上线）**：数据迁移演练通过 + 合并 main + 线上验证
