## 2. 授权、范围与约束

- 授权目标：`https://sufe-tutor.pages.dev/` 及其对应公开仓库。
- 动态方法：浏览器只读检查与 HTTP API 最小化验证；仅使用隔离账户和虚构 canary 字符串。
- 排除行为：拒绝服务、批量爆破、真实用户数据读取、持久化控制、云账号与第三方系统测试。
- 清理原则：测试合同先撤销，随后注销测试账户；不保存密码、完整 Token 或真实用户响应。

证据分级：线上已复现表示生产中观察到确定结果；线上配置确认表示由响应头、公开接口或隔离账户确认；源码审计表示当前 main 快照中的代码路径明确存在风险，但未扩大线上利用。

## 4. 详细复测结果

### F-01 公共仓库默认管理员凭据仍可接管生产

**当前等级：紧急**  
**复测结论：仍存在**

仓库根目录仍保留管理员种子配置，生产管理员账户继续接受该公开凭据。本轮再次证明公开仓库访问者可以直接获得线上管理员会话。

```text
POST /api/auth/login       -> 200
登录用户角色              -> admin
GET /api/admin/check      -> 200, isAdmin=true
POST /api/admin/invite    -> 200（仅生成隔离邀请码）
POST /api/auth/logout     -> 200
```

残余风险：

- 问题不是静态文件下载，而是有效秘密已经进入公共 Git 历史且线上密码未轮换。
- 管理员令牌仍可进一步访问用户、需求、合同、日志等高敏接口；本轮没有读取这些真实数据。

建议：立即在 D1 中重置管理员密码哈希并吊销全部管理员会话；删除并轮换仓库中的管理员密码与日志密钥，重写 Git 历史；启用管理员 MFA、短会话和首次登录强制改密。

### F-02 推送数据泄露学生及家长联系方式

**当前等级：原紧急**  
**复测结论：已修复（本轮通过）**

当前 `dbGetPendingPushesForTeacher` 统一经过 `mapDemandRow`，默认剥除 `parent_contact`、`student_contact` 与 `address_detail`。线上使用唯一 canary 联系方式验证推送列表，教师收到的响应不含 canary。

```text
POST /api/demand-pushes       -> 201
GET /api/demand-pushes        -> 200
响应中包含 canary 联系方式   -> false
```

本人需求和管理员全量接口仍按设计返回联系方式，必须持续保证归属与角色校验不被新接口绕过；联系方式仍保存在 D1 明文字段。

### F-03 合同签约失败后仍进入 signed 状态

**当前等级：原高危**  
**复测结论：已修复（本轮通过）**

当前签约路径先以 D1 batch 条件更新需求与合同，需求被合同引用时删除操作由数据层统一拒绝；线上复测未再出现待签合同被删除或签约状态不一致。

```text
创建待签合同             -> 201
删除被待签合同引用的需求 -> 409
双方签约                 -> 200 / 200
签约结果                 -> false, true
撤销合同                 -> 200
```

本轮为最小化单合同验证，未并发创建第二份真实合同；并发条件 UPDATE 与 batch 逻辑已通过源码审计。历史库仍需扫描孤立合同、悬空 `demand_id`、`signed` 但无台账等异常。

### F-04 设备接口返回账户全部完整认证令牌

**当前等级：高危残余**  
**复测结论：响应泄露已修复；数据库存储残留**

设备管理接口现在仅返回不可直接认证的 `session_id`、设备标签和时间，当前请求令牌只用于服务端判定 `current`。

```text
GET /api/auth/sessions      -> 200
返回会话条数               -> 2
会话记录含 token 字段      -> false
会话记录含 authToken 字段  -> false
```

`auth_sessions.token` 仍以完整令牌作为数据库主键保存；D1 读权限或数据库备份泄露时仍可直接冒用会话。建议迁移为 SHA-256/HMAC(Token) 摘要并吊销全部历史会话。

### F-05 教师注册与危险操作验证门控

**当前等级：高危残余**  
**复测结论：邀请码已修复；OTP 仍残留**

教师注册现在要求有效邀请码：无邀请码注册返回 400，使用管理员刚生成的隔离邀请码返回 200。但 `confirmDangerOtp` 仍无条件返回 `true`，合同撤销、账户注销等不可逆操作仍没有真实二次验证。

```text
教师无邀请码注册       -> 400
隔离邀请码注册         -> 200
源码 confirmDangerOtp  -> return true
源码 verifySignOtp     -> 当前测试版恒通过
```

建议接入真实短信/身份核验后再开放合同签署与撤销；服务端校验短时、单次、绑定用户的 OTP，并对管理员、教师审核、注销、签约和撤销合同启用重新认证与 MFA。

### F-06 敏感数据明文存储与注销清理

**当前等级：高危残余**  
**复测结论：部分修复**

注销流程已扩大：学生侧需求、意向、推送和本人评价会清理，聊天正文会匿名化；本轮两个隔离账户注销均返回 200。与此同时，联系方式、地址、教师档案、学历图片、合同正文和附件仍以业务库 TEXT/data URL 形式保存，双方共享合同/会话仍按保留策略存在。

```text
学生账户注销           -> 200
教师账户注销           -> 200
源码：student_demands / intents / pushes 按学生角色清理
源码：messages.body 仅清空本人 text 消息
```

注销清理改善了生命周期，但没有改变 D1 备份、管理员读取和数据库泄露时的明文暴露。建议实施字段级加密、私有对象存储和可审计的数据保留/注销策略。

### F-07 合同存证哈希链可验证性不足

**当前等级：中高残余**  
**复测结论：部分修复**

`ledgerContentHash` 已覆盖合同 ID、正文、`created_at` 和 `prev_hash`，修复了原先 `prev_hash` 未进入当前哈希的问题。但 `verify` 仍只重算当前合同条目，没有从链头遍历所有记录，也没有把链头锚定到独立不可回写介质。

```text
源码 contract.js:118-146
当前哈希输入：contractId + contractMd + createdAt + prevHash
验证结果：当前条目 now === row.content_hash
未发现：从 GENESIS 遍历整链或外部时间戳锚定
```

建议增加链头、序号、前条哈希和完整链遍历校验，并定期把链头摘要写入独立只写存储或可信时间戳服务。

### F-08 CSP 与安全响应头覆盖不完整

**当前等级：中危残余**  
**复测结论：部分修复**

API 响应已统一加入 CSP、HSTS、X-Frame-Options、Permissions-Policy、nosniff 和 no-store；但生产根路径响应仅有 HSTS，未返回 CSP、X-Frame-Options 或 Permissions-Policy。仓库 `_headers` 只把强规则写在 `/index.html`，而 Pages 实际首页是 `/` 的 SPA 回退。

```text
GET /api/health -> CSP=true, HSTS=true, X-Frame-Options=DENY
GET /api/health -> Permissions-Policy 已存在, Cache-Control=no-store
GET /          -> CSP=false, X-Frame-Options=null, Permissions-Policy=null
仓库 _headers:13-16 -> 强规则仅匹配 /index.html
```

建议把静态强规则改为 Pages 能命中的 `/*`，或在 Worker 静态回退统一附加同一组头，并复测 `/`、未知 SPA 路径和静态资源。随后逐步消除 `unsafe-inline`。

### F-09 限流、迁移、分页与自动化测试体系不足

**当前等级：中危**  
**复测结论：仍存在**

当前版本增加了请求体流式上限、登录长度早退、部分列表 LIMIT 和修复迁移，但速率限制仍使用单 Worker isolate 内存 Map；初始化迁移仍在请求路径执行，主要业务列表没有统一游标分页，仓库仍缺少覆盖认证/合同/隐私的 CI 集成测试。

```text
_worker.js:64-83 -> RL 使用 new Map()
_worker.js:264    -> 请求路径调用 initDb
db.js:663         -> 管理员需求 LIMIT 300，未形成统一游标分页
仓库未发现自动化安全回归测试与 CI 配置
```

建议接入 Cloudflare Rate Limiting、KV 或 Durable Object；引入版本化迁移、游标分页、复合索引、附件对象存储和 CI 安全回归。

## 5. 已确认的有效控制

- 敏感静态路径未暴露，`/_worker.js` 与未知路径仅返回 SPA HTML。
- 无效令牌访问认证、会话和会话列表会被拒绝；管理员接口需要 admin 角色。
- 教师邀请码门控已启用，注册未提供邀请码返回 400。
- 教师推送列表已使用默认需求脱敏出口，虚构联系方式 canary 未泄露。
- 待签合同引用的需求不能删除，签约和撤销状态在本轮用例中保持一致。
- 设备列表不再返回完整 Bearer Token，仅返回 `session_id` 与设备信息。
- API 安全头与 `no-store` 已上线；需补齐根路径静态头覆盖。

## 6. 整改优先级

### 6.1 立即处理：0 至 4 小时

1. 限制公网访问或启用维护页；直接重置 D1 管理员密码并吊销全部管理员会话。
2. 轮换日志密钥与所有仓库历史秘密，保存 Cloudflare、D1、GitHub 审计日志用于判断是否已被访问。
3. 将 `_headers` 的 CSP/XFO/Permissions-Policy 覆盖到实际根路径并线上复测。

### 6.2 24 小时内

1. 上线真实 OTP/MFA 或暂时关闭注销、签约、撤销等危险操作。
2. 完成 Token 摘要存储迁移并吊销旧会话；验证设备接口永不返回可认证材料。
3. 为联系方式脱敏、合同状态机和管理员种子配置加回归测试。

### 6.3 一周内

1. 完成全 API 字段可见性矩阵、历史合同/需求一致性扫描和存证链全链校验。
2. 接入持久化限流、版本化迁移、游标分页和备份恢复演练。
3. 审阅公开凭据存在期间的管理员登录、邀请发放和管理操作日志。

### 6.4 一个月内

1. 实施敏感字段与附件加密、密钥轮换、私有对象存储和数据保留/注销策略。
2. 建立 CI 安全回归、依赖扫描、事件响应预案与定期复测。

## 7. 复测限制与清理记录

本轮未执行拒绝服务、批量爆破、真实用户越权读取、管理员数据浏览、第三方云账号测试或并发大规模模糊测试。因此结论覆盖已验证路径与源码审计范围，不代表系统不存在其他问题。

- 隔离合同已撤销，返回 200。
- 学生与教师测试账户已注销，均返回 200；无邀请码分支返回 400，未创建账户。
- 第二学生会话已退出，管理员会话已退出，均返回 200。
- 未保存测试密码、完整认证 Token、邀请码或真实用户响应体。

## 8. 结论

当前版本的修复工作已经消除了四条最直接的业务利用链，但公共仓库默认管理员密码仍能接管生产，这一单点风险足以使其他访问控制失去意义。根路径安全头、恒通过 OTP、Token 明文存储、字段加密和持久化限流仍需完成后，才适合继续承载真实学生、家长和教师的敏感信息。
