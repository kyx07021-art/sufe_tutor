# 前端设计一百条原理（v1.4.0 设计轮调研产物）

> 来源：设计史（包豪斯/瑞士国际主义/新排版）、设计心理学（格式塔/认知负荷）、
> UX 法则（Hick/Miller/Tesler）、现代高端产品设计语言（Apple HIG/Stripe/Linear/Airbnb/GitHub Primer/Upwork）、
> 排版学与信息架构经典（Thinking with Type / White Space Is Not Your Enemy / Grid Systems）。
> 用途：本项目所有信息展示（卡片/详情/表单/弹窗）的设计依据——设计前查原理，禁止俺寻思。

## 第 0 条 至高原则：风格统一整齐是第一要务

> 用户定案（v1.4.1）：任何「看起来很特别」的单点特例都是缺陷——同一类信息全平台用同一字体、
> 同一字号体系、同一颜色语言。禁止给某个数据（预算/评分/报价）单独换字体、单独调字号。
> 设计时先问：「同类信息在别处长什么样？」答案一致才动手；不一致的地方优先统一，而不是新增特例。
> 排版差异只允许来自**层级**（字号/字重/间距的体系化差异），不允许来自**特例**（单点样式）。

## 一、设计史与哲学（10 条）

1. **形式追随功能**：每个视觉元素的存在理由是其功能，装饰不得凌驾于信息传达之上（包豪斯）。
2. **少即是多**：去掉一切不传达信息的装饰；怀疑每个多余的分隔线、底色、图标。
3. **内容即设计**：设计的解决方案来自内容本身（Ernst Keller）——先理解「这是什么信息、给谁看、做什么决定」，再谈外观。
4. **客观性**：设计者应作为客观的信息传递通道，不做主观的自我表达（Müller-Brockmann）——用户要看信息，不是看设计者的品味。
5. **网格系统**：用数学网格锚定所有元素，网格是最易读、最和谐的信息组织方式（瑞士国际主义）——对齐不是巧合，是系统。
6. **非对称布局**：刻意的不对称制造节奏与动感，对称易显呆板（瑞士风格）——但要平衡（视觉重量左右均衡）。
7. **左对齐、右参差**：文本块左对齐右参差比两端对齐更易读（新排版）——中文同样适用。
8. **无衬线字体的现代性**：无衬线（Helvetica/Univers）表达进步、清晰、客观；信息型界面默认无衬线。
9. **数字与文字的分离**：数字（价格/评分/时间）保持全站统一字体族，用 `font-variant-numeric: tabular-nums` 特性实现等宽对齐（v1.4.1 修正：mono 字体族只留给标识符类——邀请码/编号/版本号/代码，数据类禁用 mono 特例）。
10. **设计系统思维**：组件不是孤立的——统一的设计语言（间距/圆角/字阶/色彩 token）让产品一致可信。

## 二、视觉感知心理学（15 条）

11. **格式塔·接近性**：靠近的元素被视为一组——相关信息放一起，无关信息拉开距离。
12. **格式塔·相似性**：看起来相似的元素被视为同类——同层信息用同字体同色，异层信息必须不同。
13. **格式塔·连续性**：眼睛沿直线/曲线平滑延续——信息流按视觉路径排列，不打断。
14. **格式塔·闭合**：大脑自动补全不完整的形状——可用省略/截断，但要给足线索。
15. **格式塔·图形与背景**：前景（内容）与背景（留白）的对比决定可读性——背景必须安静。
16. **视觉权重**：大、深、高对比、人脸的元素视觉重——重点信息给重量，次要信息减重。
17. **注意力是稀缺资源**：用户扫视而非阅读——每屏只设一个视觉焦点。
18. **认知负荷**：一次展示的信息越少，理解越快——复杂信息分层呈现。
19. **F 型扫描**：文字密集页面，用户先读顶部整行、再沿左侧竖扫——最重要的放顶部与左侧。
20. **Z 型扫描**：简单页面，用户从左上到右上、斜穿到左下、再到右下——CTA 放右下。
21. **古腾堡图**：左上为最佳视觉区、右下为终点区（停留区）——身份放左上，动作放右下。
22. **Hick 定律**：选择越多决策越慢——每屏动作不超过 1-3 个主选项。
23. **Miller 7±2**：短期记忆容量约 7 项——分组/分块降低记忆负担。
24. **Tesler 定律**：复杂度守恒——把复杂度藏进设计（渐进披露），用户只看到简化层。
25. **首因效应**：第一印象在 50ms 内形成——视觉层次决定第一眼是否「可信、专业」。

## 三、视觉层次与信息编排（15 条）

26. **层次 = 对比**：没有对比就没有层次——大小/颜色/字重/留白至少一个维度拉开。
27. **尺寸是层次第一手段**：大 = 重要；标题不能与地址同字号。
28. **一个卡片一个主角**：单值卡优于双值卡——两个同等大小的数字互相竞争。
29. **信息嗅探（information scent）**：卡面信息 = 决策所需的最小集——能回答「我要不要点进去」。
30. **渐进披露**：先给最核心，细节靠交互揭示——卡面核心，详情浮窗细节。
31. **三级信息模型**：身份/标题（最大最深）→ 关键数据（次大，mono 数字）→ 元数据（小灰）——全站统一。
32. **标签订位**：给数据配标签（小灰字）——裸数字无意义（「+12% vs 昨天」好于「+12%」）。
33. **冗余消除**：同一信息只出现一次——「数学 数学: 88分」是灾难；加工数据前先查上游是否已含该信息。
34. **优先级排序**：重要信息放阅读路径起点（左/上），次要信息退到路径外。
35. **位置即层级**：右上角/右下角是注意终点——信任信号（评分）放身份行右侧，动作放右下。
36. **相似信息同形态**：同类的信息用同一种表达（所有元数据一行小灰）——形态即分类。
37. **信息分组合理化**：组内亲、组间疏（接近性）——分组标题让大段信息可扫读。
38. **列表 vs 卡片 vs 表格**：列表适合比较、卡片适合浏览抓重点、表格适合精确对照——按任务选形态。
39. **截断与省略**：长文本合理截断，但关键信息（数字/状态）永不截断。
40. **空态设计**：无数据时的空态是设计的一部分——给出引导文案，不是留白。

## 四、排版学（15 条）

41. **字阶系统**：用比例字阶（12/14/16/20/24）而非随意字号——相邻档至少 1.25× 可感知。
42. **字重纪律**：全站字重 ≤3 档（regular/medium/bold）——600 与 700 并存是混乱；用字号不用字重堆层次。
43. **正文行高**：正文 1.5-1.7 倍字号，中文至少 1.6——行高不足是拥挤感来源。
44. **行长控制**：正文每行 45-75 字符（中文 30-40 字）——超长行难读。
45. **数字排版**：价格/评分/时间用全站字体 + tabular-nums 等宽对齐（v1.4.1 修正：不换 mono 字体族——统一字体是第一优先）。
46. **数字的「大而轻」**：焦点数字用大字号 + 细字重（500），不用粗体——大而轻是高级感，大而粗是叫卖。
47. **单位降级**：数值单位（元/小时）用小灰小字跟在数字后——数字是主角，单位是注释。
48. **灰阶分层**：文字颜色用 3-4 级灰表达层级——不用彩色表达文字层级。
49. **彩色留给语义**：彩色（品牌色/状态色）只用于状态、徽章、动作——数据本身用中性色。
50. **标签小写化**：字段标签用小字（0.68-0.75rem）灰字——标签是辅助，值才是主角（Stripe 式 definition list）。
51. **标题不用装饰**：标题靠字号/字重/间距建立层次，不用下划线/边框/底色强调。
52. **编号与符号**：编号/编号标签用 mono + 等宽间距——与内容区分。
53. **行内元素基线对齐**：同一行的数字/单位/图标用基线对齐——不垂直居中散乱。
54. **断行控制**：标题/标签不随意换行——断行破坏阅读。
55. **字体一致性**：全站同一字体族（系统栈 + 一个 mono 变体）——字体多 = 廉价感。

## 五、色彩与对比（10 条）

56. **对比度 ≥4.5:1**：正文与背景（WCAG AA）——浅灰字在浅底上是可读性灾难。
57. **背景安静**：背景饱和度/明度降到最低，内容才突出。
58. **品牌色单点**：每屏品牌色出现 ≤2 处——按钮 + 焦点徽章，多则廉价。
59. **状态色语义化**：成功绿/警告黄/危险红只表达状态，不装饰。
60. **低饱和营造高级**：大面积用中性低饱和，高饱和只做小面积强调。
61. **数据不用彩色**：评分/价格用中性色（深灰/黑）——彩色留给状态，数据用形状/大小表达。
62. **悬浮/点击态**：交互元素要有明确的 hover/focus/active 状态。
63. **深色模式**：同时设计明暗两套 token——对比度在暗底上同样达标。
64. **避免纯白底**：用暖灰/冷灰底让卡片浮起——纯白刺眼且卡片无层次。
65. **阴影克制**：软阴影（低透明度大模糊）表达层级，重阴影是年代感。

## 六、空间与布局（10 条）

66. **留白是设计**：White Space Is Not Your Enemy——留白让信息呼吸，紧凑是缺陷不是默认。
67. **8px 网格**：间距用 8 的倍数（4/8/12/16/24/32）——随手数字是混乱源。
68. **亲密性**：相关元素间距 < 不相关元素间距——间距即分组。
69. **对齐系统**：同一列表的卡片边缘对齐（左对齐暗示列表）——错位让用户不安。
70. **卡片内边距**：卡片 padding ≥16px（桌面 20-24px）——内边距不足是「贴在一起」感。
71. **卡片间距**：卡片间 gap ≥12px——列表的节奏感。
72. **卡片尺寸一致**：同列表卡片同宽——尺寸变化暗示重要性变化，要刻意用。
73. **圆角系统**：圆角分级（小 6/中 12/大 16+）按组件角色——按钮与卡片不同级。
74. **弹窗宽度**：详情弹窗内容不超 2 行阅读宽度——超宽弹窗是堆砌。
75. **行网格 vs 表格**：label-value 对逐行排布，不做表格线——行网格是「账本」，分栏是「资料卡」。

## 七、信息架构与渐进披露（10 条）

76. **信息分层**：卡面（决策层）→ 详情（确认层）→ 管理（编辑层）——用户按需钻取。
77. **详情页 anatomy**：头部（身份+状态）→ 主体（分组信息）→ 动作——与卡片同构，加深不换形。
78. **标题 = 主语**：弹窗标题是内容的主语（科目/人名），不是「XX 的需求」「#0001」这类元数据。
79. **元数据不进标题**：编号/时间/状态是标签不是标题——标题只放主角。
80. **详情用 definition list**：label 小灰 + value 深色逐行——比横排堆叠可读（Stripe/Linear 式）。
81. **字段顺序按心智**：学生视角：年级→方式→时间→预算→地址（决策顺序）——不是数据库字段顺序。
82. **可选字段隐藏**：空的字段不渲染——空标签行是噪音。
83. **动作就近**：动作按钮靠近其作用的对象——距离远 = 找不到。
84. **撤销/重试**：破坏性操作有确认或撤销路径——误触是信任杀手。
85. **状态可见**：系统状态（待审核/已签约/进行中）随时可见。

## 八、卡片与组件设计（10 条）

86. **卡片 anatomy**：媒体/头像 → 标题（1-2 行）→ 元数据 → 焦点数据 → 动作——自上而下。
87. **整卡可点**：卡片主体可点击要有 hover/focus 反馈（提亮/微浮）——可点而无反馈 = 死链接。
88. **焦点可见**：:focus-visible 焦点环是全键盘可达的承诺——移除 outline 是反无障碍。
89. **内部控件短路**：卡内按钮点击不触发卡片跳转——误触是挫折。
90. **徽章克制**：状态徽章/计数 ≤2 个——徽章多 = 贴满标签的行李箱。
91. **头像即身份锚点**：头像尺寸与身份层级匹配（列表 48-64px，详情 52-72px）——人脸是天然视觉锚。
92. **评分=信任信号**：评分放身份行（星级+数字），不放大成焦点——信任信号是辅助，价格/科目才是焦点。
93. **匹配度/标签**：匹配度是「决策支持」不是「身份」——放动作区或标签位，不与身份竞争。
94. **空动作位**：无动作时卡片底部留白——没有按钮就不画按钮框。
95. **骨架屏**：加载用骨架占位——布局抖动是体验杀手。

## 九、交互与反馈（5 条）

96. **即时反馈**：点击/提交要有响应（按钮态/加载态/toast）——无反馈 = 系统死了。
97. **动效克制**：动效 ≤300ms，只表达状态变化——动效多 = 玩具感。
98. **减少模式切换**：浮窗/抽屉用于短确认，长流程用页面——弹窗堆叠是迷宫。
99. **错误信息可行动**：报错要说「怎么修」，不说「出错」。
100. **一致性 > 完美**：全站同类组件同形态同行为——局部最优不如全局一致。

## 应用到本项目的直接结论（设计轮执行依据）

- **卡片**：身份行（头像+姓名+评分右对齐）→ 焦点数据（价格大而轻，统一字体+tabular-nums）→ 元数据小灰 → 动作右对齐（#3/#27/#30/#31/#35/#86/#92）
- **需求卡**：科目=海报主标题（#27/#78），年级/方式/时间合并元数据行（#31/#36），预算独立焦点带（#46/#47）
- **详情浮窗**：标题=科目主语（#78/#79），信息用 label-value 行（#80/#81），字段按决策顺序（#81），空字段不渲染（#82）
- **年级映射**：未知 id 不显示原文（#33/#36）——脏数据不得泄漏到 UI
- **聚焦**：整卡可点 + focus-visible 焦点环 + hover 反馈（#87/#88）
- **全站**：modal 标题字重 700 不超 800（#42/#51），卡片 padding/gap 按 8px 网格（#67/#70/#71），数据中性色（#61），彩色留给状态（#49）
